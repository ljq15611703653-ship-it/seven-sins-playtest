# 七罪暗队 · 规则核心 v0.3

按《七罪暗队 · 规则草案 v0.3》实现的规则核心，纯 TypeScript，不含任何画面。
当前内容池为每罪 8 人（共 56 人）、12 张装备和 25 张槽位效果牌；FX 牌已接入混池抽取、安装与攻/血/护甲/屏障结算。
同一份代码同时用于：游戏本体（画面只负责显示和输入）、电脑对手、平衡模拟。

## 使用

```sh
npm install
npm test                          # 43 个测试
npm run typecheck
npm run sim -- roster 60000       # 人物总胜率与最强 / 最弱情境
npm run sim -- opening 400 120    # 开局胜率分布（验收标准：绝大多数落在 30%–80%）
npm run sim -- tables 100 cautious aggressive   # 整张牌桌对局（random / cautious / aggressive / bluff）
```

## 结构

| 文件 | 内容 |
| --- | --- |
| `src/content/characters.ts` | 56 名人物（每罪 8 人） |
| `src/content/tables.ts` | 12 件装备、25 张效果槽牌、27 条胜利规则、22 张场地、31 张公共效果 |
| `src/battle/engine.ts` | 回合制战斗：轮流出手、对位与转线、碰撞、形状克制环、人物能力、场地与公共效果；每次出手记一帧（事件 + 快照）给画面逐帧播放 |
| `src/battle/victory.ts` | 27 条胜利规则的判定与到时比较 |
| `src/game/table.ts` | 一张牌桌的状态机：底注、庄位、落后方选场地、布阵亮牌、两轮下注、操作费封顶、装备 / 效果槽牌混池拿牌、暗标、全押退款、结算、市场挑人、升盲 |
| `src/game/view.ts` | 每个座位能看到的信息（严格隐藏对手的暗牌）与合法动作 |
| `src/ai/agents.ts` | 随机对手、启发式对手（只读自己的观察，用战斗模拟估胜率） |
| `src/sim/` | 模拟器 |
| `web/` | 网页试玩界面（`npm run build:web` 打包） |

## 网页试玩

```sh
npm run build:web                 # 打包到仓库根目录的 sin-squad-v3/
```

`web/` 是网页界面的源码：你和电脑 1 对 1，规则全部由这里的核心驱动，界面只负责显示、点击和战斗回放。

画面是 CSS 3D 的斜放牌桌（不用 WebGL）：

- `web/morph.ts`：每次状态变化照样生成整页 HTML，但只把变化的部分套到页面上。带 `data-key` 的牌是持久的元素，可以跨区域移动（手牌拖上场、揭牌、换位时还是同一个元素），所以过渡和动画不会被打断。`data-fx` 元素和 `fx-` 开头的 class 是动画临时加的，不会被改掉。
- `web/motion.ts`：牌换位置时从旧位置滑过去、新牌发进来、出手时抬起冲撞再落回、震屏，以及浮在最上层的伤害数字、能力气泡、屏障碎片。桌面是斜的，位移先量出屏幕和桌面坐标的比例再换算。
- 每张牌分几层：`.card`（位置、冲撞）→ `.shade`（桌上的影子）→ `.lift`（抬起、扇形、受击）→ `.flip`（翻面）。`.flip` 里是一块有厚度（`--t`）的长方形：正反两面隔着厚度，四条鎏金侧边围起来，斜桌上、抬起和翻面时都看得到。暗牌亮出时是真的翻过来：先抬到离桌面半张牌宽以上，在空中翻，再落回去（`motion.ts` 的 `turnOver`；直接绕中线转会让半张牌插进桌面）。
- 牌只在换了位置（换了父元素或格子）时才滑动；原地因为整桌缩放、操作栏变高挪了一点的牌直接到位，否则每次操作栏变化整桌都会闪一下。
- 转线：对位倒下的人侧身偏向它下一次出手要打的那一边（从已经算好的战斗里往后查），挂“转线”签，直到出手才回位。牌的“前沿”朝着对面：我方是上沿、对手是下沿，所以同一方向转线时两边的旋转方向相反。
- 卡面：立绘窗、名牌、能力、底栏（左攻、中攻击形状、右血），护甲和屏障是立绘左上角的小标，都在牌框以内。卡面按自身宽度用容器查询收缩：小卡能力只留两行、连击只写分段，很小的卡只留立绘、名字和数值。
- 倾斜角度在 `style.css` 的 `--tilt`：电脑横屏 22°，手机竖屏 9°（纵向空间要留给 6 张牌加手牌），系统设置“减少动态效果”时为 0 且不播动画。
- 牌不能用负的 `translateZ`：会沉到桌面下面被盖住。3D 里也不要让两层完全贴在同一平面上（比如牌面和影子、牌行和桌面），3D 排序会让它们来回抢前后，画面闪烁；所以牌行离桌面 1px，牌面离影子 `--z0`。
- 收牌：一手结束（战斗播完点“继续”、或者有人弃牌）进入市场时，桌上两排人物和中间三块牌一张接一张抬起、翻到背面、滑到桌子右边摞起来消失，桌上只留空位。实现是 morph 的 `onExit` 钩子 + `motion.ts` 的 `collect`：要删的牌先从行里拿出来、按它在桌面坐标里的位置钉在 `.table` 上，播完再删，所以动画还在斜桌的 3D 里、也不影响新画面排版。
- 市场“发现”：候选人物浮在牌桌上方正中（桌面压暗），像炉石的发现，依次翻着升起、轻轻浮动；挑中的那张飞向挑它的人的座位，对手挑的也看得到，市场结束时没人要的沉下去。这一层一直在 DOM 里（开和关用同一个模板），牌才能从里面走退场动画。
- morph 认领到同一父元素里更靠后的带 key 元素时，跳过中间被拿走的，不去搬动它：搬动 DOM 会让元素上的 CSS 动画从头重播。
- 悬停区域是不动的影子：牌抬起后离开了鼠标，鼠标仍在影子上，不会抬起、落下来回跳。
- 场地 / 胜利规则 / 公共效果是横放在桌上的三块长条牌（`.card.tile`，同一套分层），没翻开时背面朝上；翻开时绕水平轴抬起来翻（长条牌抬半个牌高就够）。公共效果表决中金边、生效绿边、不生效变灰，都不闪。
- 规则揭晓：两张有厚度的大牌从桌面立起来、在空中翻到正面；关掉时飞回桌上对应的长条牌，落下时那块牌震一下。暗色背景画在 `::before` 上单独淡出——给装着 3D 牌的容器改 `opacity` 会把牌压平。
- 入场：起始牌池是一块斜放的小毡面桌垫，8 张牌背面朝上发上去再依次翻开（`motion.ts` 的 `turnCard`）；抛的筹码有厚度（两面之间叠 9 片金边），落在一小块毡面上；标题页七个人物排成一道弧。
- 纹章与字体：七宗罪是西方题材。`web/sigil.ts` 生成三样矢量图，挂在 CSS 变量上：
  - `--card-back` 人物牌背：一扇哥特教堂的玫瑰窗，七片大花瓣是七罪颜色的彩色玻璃（大格里高利次序：傲慢在顶，顺时针贪婪、色欲、嫉妒、暴食、愤怒、怠惰），金色窗棂、中心小七芒星、外圈放射线，双金框和四角花饰，上下 SEPTEM / PECCATA，旋转对称。
  - `--sigil` 七芒星纹章（标题页背后慢慢转的那枚）。
  - `--icon-arena / rule / pe`：场地拱门、胜利规则王冠、公共效果全视之眼。
- 场地 / 胜利规则 / 公共效果和人物牌是两个家族：人物是圆角纸牌，这三块是切角（八边形）的珐琅金属牌，青铜边、以图标为圆心的雕花细线，场地铜绿、胜利规则宝蓝、公共效果秘紫。切角会裁掉外发光，所以它们的状态框画在牌面里面。
- 展示字体用粗宋（`--display`），拉丁文装饰（七罪拉丁名、SEPTEM · PECCATA · MORTALIA、ARENA / LEX / OMEN、REVELATIO）用衬线大写（`--latin`）。
- `web/tilt.ts`：带 `data-tilt` 的元素（选对手的卡、场地候选、标题页人物）随鼠标朝玩家侧过来，鼠标下一块高光；触屏不倾斜。

打包结果是纯静态文件，本地用任意静态服务器打开仓库根目录下的 `sin-squad-v3/` 即可。这个目录不进 git：推送到 `main` 后，GitHub Actions（`.github/workflows/pages.yml`）会跑类型检查和测试、重新打包，并发布到 GitHub Pages。

**进入流程**（`web/intro.ts`）：标题页 → 选对手（三种电脑风格各有一名女性对手，半身立绘在 `web/art/foe-<风格>.webp`）→ 翻开你的 8 人起始牌池 → 抛筹码定庄（显示的就是牌桌随机出的庄家）→ “第 1 手”横幅 → 牌桌。每一步都能跳过；选对手页可以勾“快速开局”，以后直接进牌桌。

**新手提示**（`web/tips.ts`）：每个阶段第一次轮到你时，操作栏顶上出现一句说明，点“知道了”不再出现，“不再提示”全部关掉；规则页里可以重新打开。

**存档**：牌桌完全由种子决定，所以浏览器里只存种子、电脑风格、调试固定项和双方的每一步。刷新后标题页出现“继续牌桌”，照着记录重放回到原样（测试里有同样的重放检查）。规则改动导致存档对不上时会自动丢弃。

**调试模式**：网址加 `?debug` 就会跳过进入流程直接开桌，并固定下面给出的项，没给的照常随机。标题页左下角的“调试开局”也能直接输入这些参数。

```
?debug&me=EN1,GL2,PR3,WR3&foe=LU1&rule=V02&arena=A08,A02&pe=P10&market=GL2,LU2,WR3&dealer=foe&seed=42&ai=bluff
```

`me` / `foe` 是每手固定发给你 / 电脑的人物（最多 4 名，不够的随机补）；`rule`、`pe`、`arena`、`market` 分别固定胜利规则、公共效果、两张候选场地、市场；`dealer` 是第一手的庄家（`me` / `foe`）；`seed` 固定随机种子；`ai` 是电脑风格（`cautious` / `aggressive` / `bluff`）。
核心里对应的是 `new Table({ rig: { ... } })`，测试也用它固定发牌，不用靠换种子碰运气。

场地、胜利规则、公共效果的插画放在 `web/art/<编号>.webp`（A01–A22、V01–V27、P01–P31，横版 608×416）：出现在桌面中间的三块牌、选场地的选项、详情弹层、规则页列表，以及第 1 轮下注后弹出的“翻开”揭晓卡。用 NovelAI 普通生成（1216×832），画风标签和立绘一致；场地画成场景，规则画成象征物、按规则家族分色（快速击破深红、关键人物金、维持压制钢蓝、限时作战琥珀），公共效果画成奥术现象、按类别分色。

人物立绘放在 `web/art/<人物编号>.webp`（透明背景，约 416×608），打包时自动带上；没有立绘的人物用罪的纹样代替。

背景音乐放在 `web/audio/<曲名>.mp3`：`menu`（入场各屏，循环）、`bet`（牌桌各阶段，循环）、`battle`（战斗，循环）、`win` / `lose`（胜负，每场只放一次，放完回到牌桌音乐；读档摆出来的战斗不放）。打包时自动带上，换曲逻辑在 `web/music.ts`，玩家可以用顶栏或入场界面右上角的 ♪ 按钮静音。曲子用 Suno v6 生成，已去掉首尾静音、统一到 −18 LUFS，编码为 96 kbps MP3。
现有立绘用 NovelAI 的透明背景角色模式生成（只描述人物和姿势，不写背景），再按透明区域裁紧、缩放成 webp。
画风统一用这组标签开头：`1.1::artist:solipsist ::, 0.5::kakure eria ::, 0.6::VillainchinR18 ::, year 2025, 0.65::artist:windforcelan ::`；
每种罪一个主色调：愤怒深红、贪婪金、暴食橄榄绿、嫉妒青绿、怠惰灰蓝、傲慢紫、色欲玫粉。

战斗完全确定：同样的输入永远得到同样的结果。牌桌的随机数可以用种子复现。

## 代码里先做了决定、需要确认的地方

规则草案没写死的地方，代码里按下面的方式处理：

1. **护甲的“最少扣 1”按每次攻击算，不按每段算。** 按段算的话，攻 2 的连击打护甲 1 会扣 2、比重击还多，克制环就反了。现在是每段先减到 0，整次攻击只要有一段打中，至少扣 1。
2. **“保持 N 轮”**：条件成立的那一轮算起再保持 N 轮，即连续 N+1 个轮末都成立。持续优势、人数压制是“保持 1 轮”，需要 2 个轮末；旗手围困、两线推进在轮末成立就算。
3. **旗手、核心、弱点按人物卡面的基础数值锁定**，装备和下注成长不改变它们。并列取小编号。
4. **饕餮吞掉队友后，空出来的位置对对手公开**（桌上确实少了一张牌），对手因此能推断出饕餮在场。
5. **静默书库**：开战时的能力全部不发动（包括夺装、缔结、魅惑、下注层能力），第 1 轮的战斗能力也失效；沉眠巨像“前两轮不出手”的限制照旧。
6. **夺装者**同时拿走对位的装备；两个夺装者对位时互换。
7. **同行药袋**守护两侧所有相邻队友；攻击被改到它身上后，不再享受“打对位”的加成。
8. **暗标出价相同时**，公共效果不生效，双方都不付钱。
9. **装备**：12 件，6 件身材牌、6 件改形状或加防御，见 `tables.ts`。
10. **市场第三阶段**（第 11 手起的“罪王”级人物）还没有单独分池，暂时用第二阶段的人物代替。
11. **全押后**不再进行后面的下注和操作；如果胜利规则还没翻开就翻开，但尚未翻开的公共效果不生效。
12. **轮流出手**：每轮双方交替出手，同一方按 1→2→3 号位，每人一次；第 1 轮由非庄家先手（庄家后布阵、有信息优势），之后每轮换另一方先手。每次攻击后立刻结算，不需要“保持”的规则（击倒类、关键人物）当场判定；需要保持的规则和轮末效果在轮末结算。同一次碰撞里双方同时达成（例如同归于尽）算平局，双方拿回各自投入。
13. **碰撞**：每次攻击都是一次碰撞，被打的人把自己的攻整段打回攻击者（像酒馆战棋）。反击按攻击者的屏障、护甲正常结算（屏障能整段挡掉，每次至少扣 1），不触发“沉重后坐”。这一轮不出手的人（沉睡、缔结、被定住）和正在转线的人不反击。
14. **吸血**：嚼盾兽自己主动攻击每打中一段回 1 血（连击两段都打中就回 2）；反击不回血（否则攻不超过 3 的对手永远打不动它）。被护甲吃光、被屏障挡掉的那段不算打中。枯水、终场冲刺让吸血每次少回 1。
15. **身材比例**：攻 1–5、血 3–13，攻血比约 1 比 3。一场平均约 2.75 轮、9 次出手。按时间触发的场地和公共效果相应提前；“保持”类规则缩短为保持 1 轮或轮末成立即胜，限时规则缩短为 3–4 轮。
16. **窥视者**：偷看不写进公开的牌桌记录，对手不会知道。偷看之后可以交换自己两名暗置人物的位置（亮出的那名、空位不能动）；如果对手也偷看过被换走的人，他看到的信息跟着这名人物走。
17. **所有结算都是整数**：连击把伤害拆成两段整数，奇数时后一段多 1（攻 3 是 1+2，屏障先挡掉小的那段）；减半类效果向下取整，+25% 四舍五入。卡面直接写出连击分段，比如“连击 1+2”。

## 模拟现状（供调平衡参考）

- **战斗节奏**：平均约 2.75 轮、9 次出手；第一个人平均在第 4 次攻击后倒下。
- **先后手**：先手一方胜率约 51%，碰撞让先手几乎没有优势。
- **开局胜率**：最差一成约 38%、中位 50%、最好一成约 63%，98.5% 落在 30%–80%，已达标。
- **人物胜率**：全部在 45%–55% 之间。残羹客最高（54.2%），窥视者最低（45.3%）；窥视者、炫耀者的价值依赖情报和亮牌决策，随机模拟会低估它们。
- **平局约 9%**：同一次碰撞里双方同时达成一律算平局，约四成是双方全灭，其余多是“第一滴血”这类规则下一次碰撞各倒一人。
- **先击倒的一方约 77% 会赢**（同时出手时是 82%）。还需要“复仇”类人物能力来进一步削弱滚雪球。
- **牌桌太短**：电脑对手很快全押，一张牌桌平均只打 5–7 手，远少于设计的十几到二十手。需要调整携入金额、底注或下注上限，也需要更好的电脑对手。
- **效果槽牌**：FX01–FX25 已接入为静态面板修正（每人身上一件装备、一张效果槽牌，互不顶替）；原设计中依赖攻击、治疗、状态和时间事件的复杂触发，仍需事件级实现后才能恢复原文效果。
